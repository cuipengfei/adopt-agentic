# Human-in-the-Loop：你才是最终决策者

> **上下文视角**：你，作为人类用户，是上下文流动的最后一道关卡。Agent 的所有产出，最终由你决定是接受、修正，还是丢弃。

## 你在工作流中的角色

前面的章节都在讲 Agent 的机制：它如何理解、如何行动。

现在，回到你。

你不是被动的观众，你是 Agent 工作流中不可或缺的一环——**监督者、决策者、纠偏者**。你决定了 Agent 创造的价值能否真正落地。

Agent 是你的副驾驶。它能分担大量工作，但方向盘最终在你手里。

## 放手 vs. 介入：一个决策框架

什么时候可以让 Agent 自主飞行，什么时候必须人工介入？这不是一个感性问题，而是一个风险评估问题。

你可以用这个简单的框架来做决策：

| 风险象限 | 任务特征 | 你的策略 | 示例 |
|:---:|---|---|---|
| **低风险 / 可逆** | 影响范围小，易于回滚，验证成本低 | **放手（Auto-Approve）** | - 生成单元测试<br>- 重构纯函数<br>- 撰写文档初稿 |
| **中风险 / 可控** | 涉及多个文件，但有版本控制，可快速回滚 | **观察并抽查** | - 添加新特性<br>- 修改 API 接口<br>- 升级依赖包 |
| **高风险 / 不可逆** | 操作生产环境，删除数据，对外发布 | **强制审批（Manual Gate）** | - 数据库迁移<br>- `git push --force`<br>- 部署到生产 |

核心原则：**操作的潜在负面影响越大，你的介入就应该越深。**

## 审批点设置

对于高风险操作，你需要在 Agent 的工作流中设置明确的**人工审批点**。

这就像核潜艇的发射钥匙，必须由你转动。

Agent 应该在执行以下操作前，明确请求你的批准：

- **对外写操作**：`git push`、发布 npm 包、部署网站。
- **破坏性操作**：删除文件、`git reset --hard`、清理数据库。
- **成本敏感操作**：运行昂贵的 API 调用、触发大规模 CI/CD 流程。

好的 Agent 工具会默认在这些操作前暂停，并提供清晰的 diff 对比，让你一目了然地做出决策。

## 纠偏策略

当 Agent 跑偏时，你有三个选择：

1.  **立即打断**：适用于 Agent 从一开始就理解错你的意图，或者正在进行明显错误的操作。这是最直接的方式，避免浪费时间。
2.  **让它跑完再改**：适用于 Agent 的整体方向正确，但实现细节有瑕疵。让它完成整个任务，然后你再基于它的产出进行修正。这保留了 Agent 的大部分工作成果。
3.  **放弃并重来**：适用于上下文已经被严重污染，或者任务过于复杂，Agent 陷入了无法恢复的混乱。此时，放弃当前会话，开一个新的、干净的会话，用更清晰的指令重新开始，通常比在泥潭里挣扎更高效。

选择哪种策略，取决于你对**“沉没成本”**和**“未来收益”**的判断。

## 认知债务：过度委托的代价

有一个隐蔽的风险需要警惕：**认知债务**。

当你过度依赖 Agent，让它包办所有事情时，你对系统的理解可能会逐渐被稀释。代码是 Agent 写的，Bug 是 Agent 修的，架构是 Agent 调整的——几个月后，你可能已经不清楚某些模块的工作原理了。

这是一种技术债，但负债的不是代码，而是**你和团队的认知**。

如何缓解认知债务？

- **定期 Code Review**：像 review 同事的代码一样，认真 review Agent 的提交。
- **自己动手**：对于核心或复杂的模块，坚持自己动手或与 Agent 结对编程，而不是完全委托。
- **画架构图**：定期让 Agent 生成或更新系统的架构图、数据流图，帮助你维持对系统全局的理解。

记住，Agent 是放大你能力的工具，不是取代你思考的工具。

## 横切关注点

- **上下文流动**：你通过批准、拒绝或修正，将自己的决策反馈注入上下文，引导 Agent 的下一步行动。Agent 的产出是你决策的输入，你的决策是 Agent 下一轮推理的输入。
- **风险提示**：最大的风险是**过度信任和过度委托**，导致认知债务累积和对系统的失控。另一个风险是**审批疲劳**，对 Agent 的请求不假思索地一路绿灯。
- **可审计性**：你做出的每一次介入决策——批准、拒绝、编辑了什么内容——都应该被记录下来。这不仅是追溯问题的原因，也是复盘和改进你与 Agent 协作模式的宝贵数据。
