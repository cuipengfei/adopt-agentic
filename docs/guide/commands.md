# 命令（Slash Commands）

> **上下文视角**：命令是用户侧的上下文注入快捷方式 — 将预定义 prompt 模板一键送入上下文。

## 定义：什么是命令

一个以 `/` 开头的短语，比如 `/review` 或 `/commit`。

它不是聊天。它是一个**预设的指令模板**。你输入 `/review`，Agent 不会和你闲聊 review 的哲学，而是立刻开始执行一套 review 代码的预定动作。

这些动作被定义在某个地方——可能是 Agent 自带的，也可能是你配置的。

## 本质：模板化的上下文注入

命令的本质，是**把一段预先写好的、可能很复杂的 prompt，打包成一个快捷方式**。

当你执行 `/review` 时，背后发生的事情可能是这样的：

Agent 读取 `/review` 命令关联的模板，模板内容可能是：

```
1. **识别变更**：对比当前分支与主干分支，找出所有被修改的文件。
2. **分析代码**：对每个变更的文件，检查代码风格违规、潜在 bug 和可改进之处。特别关注：命名不一致、可简化的复杂逻辑、缺失的错误处理。
3. **总结发现**：生成一个简短的报告，用项目符号列表总结每个文件的关键问题和建议。
4. **呈现报告**：将报告输出到当前对话中。
```

Agent 将这段文本——连同它找到的文件变更——一起塞进发往 LLM 的请求中。

```json
// → REQUEST（agent → LLM API）
{
  "system": "你是一个资深代码评审员...",
  "messages": [
    // ... 对话历史 ...
    {
      "role": "user",
      "content": "请遵循以下步骤进行代码评审：\n1. **识别变更**：对比当前分支与主干分支...\n2. **分析代码**：...\n\n变更文件 `index.js` 内容如下：\n// ... 文件内容 ..."
    }
  ]
}
```

LLM 并不知道你输入了 `/review`。它看到的只是一个非常具体的、结构化的指令。对它来说，这和用户手动输入一大段文字没有区别。

命令，就是**上下文注入的快捷方式**。

## 可内嵌内容

命令不只是纯文本。一个设计良好的命令系统，可以让你把多种元素打包在一起：

-   **纯文本 Prompt**：最基础的指令和问题。
-   **执行 Shell 命令**：比如 `/commit` 命令可能包含 `git status` 和 `git diff --staged` 的执行步骤，并将结果注入上下文。
-   **读取文件内容**：比如 `/test [文件名]` 可以读取指定测试文件和被测文件，然后要求 LLM 跑一个思维实验。
-   **组合动作**：一个 `/publish` 命令可以依次执行 lint、test、build、bump version 等一系列动作。

## 与系统指令（System Instructions）的区别

| 特性 | 系统指令 (System Instructions) | 命令 (Slash Commands) |
| :--- | :--- | :--- |
| **存在感** | **始终存在**，贯穿整个会话 | **按需触发**，一次性注入 |
| **作用域** | 全局，影响 Agent 的每一次响应 | 局部，只影响当前这一轮任务 |
| **角色** | Agent 的"性格"和"行为准则" | 一次具体的"任务清单" |
| **示例** | "你是一个 Python 专家，代码要符合 PEP8 规范" | `/test` |

系统指令是 Agent 的背景音乐，始终在播放。命令则是一首被点播的歌曲，播放一次就结束了。

混淆这两者，就像要求一个性格沉稳的 Agent（由系统指令设定）突然去执行一个风格激进的发布脚本（由命令触发）。Agent 会感到困惑，最终结果可能两边都无法满足。

## 横切关注点

-   **上下文流动**：用户输入 `/command` → Agent 将其展开为一段具体的 prompt → 注入 `messages` 数组 → LLM 消耗这段 prompt → 生成响应。
-   **风险提示**：定义不清或过于复杂的命令可能与现有的上下文（包括系统指令）冲突，导致 LLM 收到矛盾的指令。比如，系统指令要求"谨慎操作"，而 `/force-push` 命令要求"强制覆盖"。
-   **可审计性**：Agent 的日志应该清晰记录是哪个命令触发了后续的一系列动作。当出现非预期行为时，能追溯到源头的命令定义，是排查问题的关键。
