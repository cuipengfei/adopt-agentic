# Review: 节点 6 — Slash Commands

## 总评
基础质量合格，主线方向正确，但"承上启下"和"精确边界"还不够硬。当前稿子已经清楚讲出"Slash Commands = 按需上下文注入"，但与前后节点（MCP、Skills）的链路感偏弱。
建议做一轮小幅重构，不改框架，只补关键桥段和术语精度即可。

> ★ Insight：这篇最大价值点已经有了（"命令不是魔法，是 prompt 展开"）；下一步不是"加内容"，而是"把边界讲准 + 把章节链路接上"。

## 逐维度

1. **写作风格（十人混血儿）**：**7.5/10**
   优点：短句、直给、例子先行。
   问题：个别比喻略多（如"背景音乐/点播歌曲"），相较 `context.md` 的硬核密度略松。

2. **精简度**：**8/10**
   总体不冗长，但"命令=快捷方式"在"定义/本质"两段有轻微重复。
   可合并 1-2 句，提升压缩比。

3. **上下文主线：按需注入**：**8/10**
   主线是对的，已明确注入 `messages`。
   但"只影响当前这一轮"表述偏绝对，实际通常影响该任务的后续轮次（直到被新上下文稀释/截断）。

4. **Commands vs System Instructions 区别**：**8.5/10**
   对比表很清楚，是本稿强项。
   建议把"作用域"改成"默认局部、任务级；非全局常驻"，更准确。

5. **具体 command 例子**：**7.5/10**
   有 `/review`、`/commit`、`/test`、`/publish`，方向正确。
   但缺一个"输入命令 → 模板展开 → 本地动作结果注入 → 下一轮请求"的完整闭环示例。

6. **Agent Agnostic**：**9/10**
   合格，未产品绑定。

7. **中英文质量对等**：**8/10**
   结构和信息基本对齐。
   英文个别语气略口语（如 "stuffs it into..."），专业感比中文版稍弱。

8. **横切关注点**：**9/10**
   三项齐全，格式合规。
   可再补一条"高风险命令需确认门槛"的操作性细节。

9. **与前后节点衔接（MCP→Commands→Skills）**：**6.5/10**
   当前几乎是独立讲解，缺显式桥接句。
   建议补两句：**MCP 解决"能调用什么能力"，Commands 解决"何时触发哪段任务上下文"，Skills 解决"长期行为模式如何持续生效"。**

## 具体修改建议
- [ ] 在"定义/本质"间去重 1 段，保留最硬定义。
- [ ] 将"只影响当前这一轮任务"改为"任务级局部生效，非全局常驻"。
- [ ] 增加一个 2 轮闭环示例（含 `→ REQUEST` / `← RESPONSE` / 本地动作结果回注）。
- [ ] 开头加承接 MCP 的过渡句（能力来源 vs 触发方式）。
- [ ] 结尾加铺垫 Skills 的过渡句（一次性注入 vs 持续行为）。
- [ ] 英文稿把口语词替换为技术中性表达（如 "injects into request"）。
- [ ] 横切关注点中补"高风险 command 需人工确认/审批"一句（中英同步）。
