# Review: 节点 3 — System Instructions

## 总评
当前 draft 的骨架是对的：主命题、关键洞察、横切关注点都在；但在"基准风格对齐"和"前后节点衔接"上还不够锋利，且 HTTP/SSE 展示不完整（只有 request，没有成对的 response/多轮）。
结论：这是**可发布前的 first pass**，建议做一轮短平快重写，重点补"二轮示例+承接句+去冗余"。

## 逐维度评估

1. **写作风格（对照 context/actors）**：**部分达标**
   - 优点：开篇定义清楚，结构完整。
   - 差距：相比基准页，句子偏长、解释性偏多、节奏不够"短句+结论句"。

2. **精简度**：**有明显可删空间**
   - `它是如何工作的` 与后文多处重复"每轮都存在/持续约束"。
   - `它包含什么` 每条示例偏长，可每条只保留一个例子。

3. **上下文主线（第一份上下文）**：**达标但可更硬**
   - 已明确"第一份、最高优先级上下文"。
   - 还缺"Agent 在每轮请求都把它放在最前面"的可视化证据。

4. **HTTP/SSE 模式**：**部分达标**
   - 有 request 体且 `system` 位置清楚。
   - 缺 SSE response 块、缺"第 2 轮 messages 变长但 system 不变"的对照。

5. **关键洞察（最强杠杆 + 可维护资产）**：**达标**
   - 两个洞察都有独立章节，方向正确。
   - 可再收紧措辞，避免口号化（如"没有之一"）。

6. **读者定位（用 agent tool 的开发者）**：**部分达标**
   - 大部分内容贴近开发者场景。
   - "你不需要学习写代码"与目标读者不完全一致，建议改为"不需要改 agent 内核"。

7. **Agent Agnostic**：**基本达标**
   - 未绑定单一产品，示例总体中性。
   - 可减少品牌化命名（如示例里的专有助手名）以更通用。

8. **中英文质量对等**：**结构对等，细节不对等**
   - 章节和论点基本镜像。
   - 中文有细节问题：`系统-指令`、`会話`；英文行文更顺，中文需打磨节奏。

9. **横切关注点齐全**：**达标**
   - 三项齐全且方向正确。
   - 可把"可审计性"再落到"请求体/日志可导出回放"的具体动作。

10. **与前后节点衔接（actors → built-in-tools）**：**不足**
   - 没有显式承接 `actors`：谁负责注入 system。
   - 对下一节 `built-in-tools` 的铺垫较弱。

## 具体修改建议
- [ ] 在"它是如何工作的"改成**两轮最小示例**：第 1 轮 request+SSE response；第 2 轮 request（`messages` 变长）并显式保留同一 `system`。
- [ ] 开头加 1 句承接：基于 `actors`，**Agent 负责把 system 注入每次 API 请求**，LLM 只消费。
- [ ] 结尾加 1 句铺垫下一节：**built-in tools 的定义与返回值如何进入同一上下文回路**。
- [ ] 把"你不需要学习写代码"改为"你不需要改 agent 内核/框架，也能显著改变行为"。
- [ ] 精简 `它包含什么`：每个 bullet 保留一个例子，删除第二个括号例子。
- [ ] 删减重复句：把"每轮都存在、持续约束"保留一次最强表述即可。
- [ ] 修复中文细节：`系统-指令` → `系统指令`；`会話` → `会话`。
- [ ] 统一术语策略：正文主用"系统指令（system instructions）"，仅首次提到"system prompt"别名。
- [ ] 将比喻句（信封/邮差）压缩为一句，避免抢占技术解释篇幅。
- [ ] 英文稿同步同幅度改写，确保"信息密度、句长、节奏"与中文版一致。
