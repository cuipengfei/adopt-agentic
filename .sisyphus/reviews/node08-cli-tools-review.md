# Review: 节点 8 — Agent-Native CLI Tools

## 总评
当前稿子结构完整、主线正确，HTTP 两轮示例和横切关注点都到位，已经是可发布前的"可用草稿"。主要短板是：表达有重复、个别技术表述过度简化（尤其 MCP/管道示例）、以及与前后节点衔接不够显式。
**Effort estimate：Short（1–4h）**

## 逐维度评审

1. **写作风格（十人混血儿）**：**7.5/10**
   优点：开场直给、例子先行。
   问题：比 `context.md`、`actors.md` 更"说明文"，狠劲和节奏感稍弱，存在"解释同一件事多次"的冗余。

2. **精简度**：**7/10**
   核心观点在多处重复。可压缩约 15–20%，不损信息密度。

3. **上下文主线（CLI 输出即上下文）**：**9/10**
   主线清晰且贯穿。建议补一句"exit code/stderr 也是上下文信号"。

4. **Unix 哲学与 agent-native 契合**：**8/10**
   框架正确，三点契合讲清楚了。
   但示例 `rg "error" | jq .message` 技术上不稳（`rg` 默认非 JSON 输出），建议换成可直接成立的组合示例。

5. **与内置工具/MCP 区别清晰度**：**7/10**
   表格易读。但"MCP = 标准化网络协议 (HTTP)"过窄，建议改成"协议层抽象，可基于 stdio/HTTP 等传输"。

6. **HTTP 模式（agent 通过 bash 调 CLI 流程）**：**8.5/10**
   两轮 request/response + 本地执行都写到了。可再对齐 `context.md` 写法：第二轮注释明确"messages 比第一轮更长"。

7. **Agent Agnostic**：**9.5/10**
   全文保持通用术语，无产品绑定。

8. **中英文质量对等**：**8/10**
   结构和信息量基本镜像。英文个别句子不够地道，可做一轮母语化润色。

9. **横切关注点齐全**：**10/10**
   三项齐全，且内容不空泛。这一段是整篇质量较高的部分。

10. **与前后节点衔接（承接 Skills，铺垫 knowledge-feeding）**：**6.5/10**
   缺少承接 Skills（为何从"能力包"转到"执行接口"）和引出 knowledge-feeding（CLI 输出如何沉淀为可复用知识）。

## 具体修改建议
- [ ] 删减重复表述：保留"CLI 输出即上下文"一次主论断 + 一次回扣即可。
- [ ] 把 `rg | jq` 示例改为技术上稳定的管道示例（如 `curl ... | jq ...`）。
- [ ] 修正 MCP 行的接口描述，避免把 MCP 限定为 HTTP。
- [ ] 在 HTTP 第二轮注释补"messages 变长"提示，对齐基准文风。
- [ ] 在"上下文流动"处补 `exit code` 作为决策信号。
- [ ] "设计启示"从绝对口吻改为条件口吻。
- [ ] 开头加 1 句承接 Skills（技能决定"知道什么"，CLI 决定"如何取证/执行"）。
- [ ] 结尾加 1 句引向 knowledge-feeding（CLI 产出的结构化文本如何沉淀为持久上下文）。
- [ ] 英文稿做一轮母语化精修。
- [ ] 中英文术语做镜像校对。
