# Inline Review：评论驱动的内容审校工作流

用户在内容文件中以 HTML 评论（`<!-- ... -->`）或 YAML 注释（`# ...`）的方式留下 inline 反馈。Agent 读取这些评论，归纳通用规则，更新项目配置，然后执行改进。

## 适用场景

- 用户说"看看我留的评论"、"读一下我的反馈"、"check my comments"
- `git diff` 中出现 `<!-- ... -->` 格式的新增评论
- 用户在 frontmatter 中留了 `#` 注释

## 工作流（严格按顺序执行）

### Phase 1：发现评论

```bash
git status          # 找到哪些文件被修改
git diff            # 读取所有修改，包括评论
git diff --cached   # 也检查已暂存的修改
```

从 diff 中提取所有 `<!-- ... -->` 和 YAML `# ...` 格式的评论。同时注意用户做的直接文字修改——这些修改本身也是反馈信号（比如拆段、删词、改标题）。

### Phase 2：归纳模式

把所有评论 + 直接修改归纳为**通用规则**。

关键思维：

- **不只解决个例**——从具体评论中提炼出可复用的通用规则
- **按维度分类**——术语、逻辑、呼吸感、可视化、风格等
- **给出禁用/替换表**——如果评论指出某个词不好，整理成禁用词 → 替代词的映射

归纳结果呈现格式：

```
| # | 模式名称 | 典型评论 | 通用规则 |
|---|----------|----------|----------|
| 1 | xxx | "原始评论" | 规则描述 |
```

### Phase 3：更新项目配置

把归纳出的通用规则写入 `CLAUDE.md`（本项目不用 AGENTS.md）。

更新位置：
- 写作相关规则 → `CLAUDE.md` 的"写作纪律（审校规则）"部分
- 视觉/设计相关 → `CLAUDE.md` 的"已知问题 / TODO"部分
- 技术约定相关 → `CLAUDE.md` 的相应技术部分

更新原则：
- **增量更新**——追加新规则，不覆盖已有规则
- **去重**——如果新规则和已有规则重复，跳过
- **保持结构**——遵循 CLAUDE.md 现有的格式和层级

### Phase 4：执行改进

基于评论执行具体的内容修改。

执行顺序：
1. **先改被评论的文件**——修复评论指出的具体问题
2. **删除已处理的评论**——修复完毕后，把对应的 `<!-- ... -->` 评论删掉
3. **全局扫描**——如果新规则涉及术语禁用等全局规则，扫描所有内容文件
4. **双语同步**——中文改了，英文必须同步
5. **Build 验证**——`bun run docs:build` 必须通过

### Phase 5：向用户汇报

汇报格式：

```
### CLAUDE.md 更新
- [新增了什么规则]

### 内容修改
| 文件 | 改动 |
|------|------|
| xxx.md | 修复了什么 |

### 全局影响
- [如果有全局扫描/替换，列出影响的文件和数量]
```

## 评论识别规则

| 格式 | 场景 | 示例 |
|------|------|------|
| `<!-- 评论内容 -->` | Markdown 正文中的 inline 反馈 | `<!-- 这个术语太装逼 -->` |
| `# 评论内容` | YAML frontmatter 中的反馈 | `# icons should be consistent` |
| 直接文字修改 | 用户直接改了文字（从 diff 中识别） | 拆段落、删词、改标题 |

## 注意事项

- **必须加载配套 Skills**——审校 `docs/` 下教程内容时，必须同时加载 `humanizer-zh`（去 AI 痕迹）和 `adopt-agentic-writer`（十人混血儿写作风格 + HTTP/SSE 模式）。主 agent 亲自编辑时遵循这两个 skill 的规则；委托 sub-agent 时通过 `load_skills` 传入
- **不要擅自修改用户没评论的地方**——只改评论指出的问题 + 新规则涉及的全局问题
- **评论是反馈不是指令**——需要理解评论背后的意图，不是机械执行
- **保持写作风格**——所有修改必须遵循 CLAUDE.md 中的"十人混血儿"写作风格
- **不要用 sub-agent 做文本编辑**——风格一致性要求主 agent 亲自操刀
- **可以用 sub-agent 做辅助工作**——全局术语扫描、视觉设计等可以委托
